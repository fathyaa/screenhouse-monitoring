Demo Grafik Metrik Kualitas

Preview visual untuk bab evaluasi TA. Data contoh dari metrics-bar.csv dan metrics-boxplot.csv. Sumbu X = Increment 1 · 2 · 3 (sesuai catatan dosbing).

⚠ Data ilustrasi — ganti setelah uji nyata

📊 Bar chart

Satu batang = satu angka (pass rate, error rate, completeness). Cocok metrik fungsional & error.

📦 Box plot

Satu kotak = banyak pengukuran (10 run). Garis tengah = median. Cocok latency & throughput.

Cara baca box plot

Yang dosbing gambar di kertas (kotak + ekor atas bawah) kira-kira seperti ini:

Latency (ms)
 910 ┤                              ┬  ← max
 850 ┤                              │
 800 ┤                         ┌────┤  ← Q3 (75%)
 790 ┤                         │ ───│  ← median ★ laporkan ini
 760 ┤                         └────┤  ← Q1 (25%)
 720 ┤                              ┴  ← min
     └──────────┬──────────┬──────────
            Increment 1   2        3

  • Kotak = 50% data di tengah (stabil atau tidak)
  • Increment 3 lebih tinggi = wajar (alur alert lebih panjang)

Gambar 4.1 — Pass Rate & Error Rate (Bar Chart)

Metrik fungsional + error per increment. Target dosbing: error turun, pass rate naik.

Gambar 4.2 — Kelengkapan Fitur / Komposisi (Bar Chart)

Berapa % fitur yang direncanakan di increment sudah jalan dan lulus UAT.

Gambar 4.3 — Latency API (Box Plot)

10× pengukuran response time endpoint per increment. Inc 2 lebih berat (query tren), Inc 3 (pipeline alert).

Gambar 4.4 — Latency End-to-End detik (Box Plot)

MQTT publish → data/alert tampil di UI. Satu angka per run, 10 run per increment.

Gambar 4.5 — Throughput (Box Plot)

Request/transaksi berhasil per detik saat load test ringan.

Gambar 4.6 — Ringkasan Atribut Kualitas (Grouped Bar)

Availability, Security, Reliability — satu grafik untuk atribut non-fungsional dosbing.
